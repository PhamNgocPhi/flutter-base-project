# Fluenary

[Tiếng Việt](README.md) | **English**

Base Flutter app (mobile only: Android + iOS) using **Flutter 3.47.0 / Dart 3.13**, feature-first architecture with Bloc/Cubit, 3 flavors `dev` / `stg` / `prod`.

Goal: clone into a new project in minutes — everything cross-cutting (env, network, DI, logging, theme, i18n, router, error handling) is already wired up.

## Stack

| Layer | Package | Notes |
|---|---|---|
| Version pin | [FVM](https://fvm.app) (`.fvmrc`) | Always use `fvm flutter` / `fvm dart` |
| State | `flutter_bloc`, `bloc`, `equatable` | Cubit for simple features, Bloc for complex ones |
| DI | `get_it` | Registered manually in `lib/core/di/injection.dart` |
| Navigation | `go_router` | Route names centralized in `lib/app/router/routes.dart` |
| Network | `dio` | Auth + log interceptors (Talker) |
| Env / flavor | `envied`, `flutter_flavorizr` | Config read from `env/.env.<flavor>`, obfuscated at build time |
| Models | `freezed`, `json_serializable` | DTOs in the data layer, Entities in the domain layer |
| Storage | `shared_preferences`, `flutter_secure_storage` | Wrapped in `AppStorage` |
| i18n | `flutter_intl` / `intl_utils` | ARB in `lib/l10n/`, generated `S` class in `lib/generated/` |
| Logging | `talker`, `talker_flutter`, `talker_dio_logger`, `talker_bloc_logger` | In-app log viewer screen (`/logs`) |
| Test | `bloc_test`, `mocktail` | |

## Getting started

```bash
# 1. Install the Flutter version pinned in .fvmrc
fvm install

# 2. Create env files from the examples (only *.example is committed)
cp env/.env.dev.example  env/.env.dev
cp env/.env.stg.example  env/.env.stg
cp env/.env.prod.example env/.env.prod

# 3. Fetch dependencies + generate code (envied, freezed, json, l10n)
make get
make gen

# 4. Run the dev flavor
make run-dev
```

In VS Code: open the Run panel and pick the `dev` / `stg` / `prod` configuration (already in `.vscode/launch.json`).
In Android Studio: pick the matching run configuration (generated by flavorizr in `.idea/`).

### Architecture conventions

- **Feature-first**: each feature owns its data/domain/presentation. Deleting the feature folder + removing its registrations in `injection.dart` and `app_router.dart` removes it completely.
- **Selective Clean Architecture**:
  - Simple features (forms, static screens, counters…): only `presentation/` with Cubit + Screen. See `features/home`.
  - Complex features (API calls, many business rules, need thorough testing): all 3 layers. See `features/example`.
- **Cubit vs Bloc**: Cubit when state changes via direct method calls; Bloc when you need an event stream, debounce/throttle, or multiple events affecting the same state.
- **No `try/catch` in Blocs**: repositories return `Result<T>` (`Success` | `Error`) via `guard()`, and Blocs `switch` on the result.
- **No `BuildContext` outside widgets**: Blocs/usecases/repositories receive dependencies only via constructor (from `getIt`).

## Flavors & Env

### How it works

```
env/.env.dev  ──envied──▶  lib/core/env/env_dev.g.dart  ──▶  EnvDev  ──▶  bootstrap(EnvDev())
                                                                              └─ getIt<AppEnv>()
```

- Each flavor has one `env/.env.<flavor>` file and one `Env<Flavor>` class implementing `AppEnv`.
- Values are **obfuscated** into the binary at build time (`@Envied(obfuscate: true)`); no file is read at runtime.
- Read config anywhere: `getIt<AppEnv>().apiBaseUrl`.

### Adding a new env variable

1. Add the line to all 3 `env/.env.*` files **and** the 3 `.example` files.
2. Add a getter to `AppEnv` (`lib/core/env/app_env.dart`).
3. Add an `@EnviedField` to `EnvDev`, `EnvStg`, `EnvProd`.
4. `make gen`.

## Localization

- Source: `lib/l10n/intl_vi.arb` (primary locale `vi`). To add a language: create `intl_en.arb` with the same keys.
- Generate: `make l10n` (or the *Flutter Intl* IDE plugin regenerates on ARB save).
- Use in widgets: `context.l10n.home` (extension in `core/utils/context_ext.dart`).
- Placeholders:

```json
"counter": "Bạn đã nhấn {count} lần",
"@counter": {"placeholders": {"count": {"type": "int"}}}
```

→ `context.l10n.counter(3)`.

## Networking

- There are **2 Dio instances** in DI (`core/network/dio_client.dart`):
  - `getIt<Dio>()` — main Dio with `AuthInterceptor`. Use for all business APIs.
  - `getIt<Dio>(instanceName: plainDio)` — "plain" Dio without the auth interceptor. Only for login/refresh, to avoid loops.
- `baseUrl` and timeouts come from env. Requests/responses are logged via `TalkerDioLogger`, only when `ENABLE_LOG=true`.
- Requests that don't need a token: `Options(extra: {AuthInterceptor.noAuth: true})`.
- Errors are normalized in `core/error/failure.dart`:
  - `NetworkFailure` — timeout / no connection
  - `ServerFailure(statusCode, message)` — HTTP error, `message` taken from `response.data['message']`
  - `UnknownFailure`

## Auth & refresh token

### Flow

```
                    ┌────────────── proactive ──────────────┐
request ──▶ AuthInterceptor.onRequest ──▶ TokenManager.validAccessToken()
                                             │ access token about to expire (exp - 30s)? → refresh()
                                             ▼
                                        attach Bearer ──▶ server
                                                          │ 401?
                                                          ▼
                    AuthInterceptor.onError ──▶ TokenManager.refresh() ──▶ retry original request (once)
                                                     │
                                       ┌─────────────┴──────────────┐
                                  refresh OK                  refresh 401/403
                                  store new tokens            clear tokens + AuthEvent.sessionExpired
                                                                     │
                                                              AuthCubit → Unauthenticated
                                                              GoRouter.redirect → /login + snackbar
```

### Design decisions

| Problem | Solution |
|---|---|
| N concurrent 401 requests | `TokenManager.refresh()` locks with a `Completer`: only 1 real refresh request, other callers await the shared result. Tested: `5 concurrent refreshes call the datasource only once`. |
| refresh → 401 → refresh loop | Login/refresh use the "plain" Dio + `extra[noAuth]`; retried requests are marked `extra[retried]` and never retried twice. |
| Refresh network error | **No logout.** `refresh()` throws `DioException`, the original request fails like a normal network error. Only 401/403 from the refresh endpoint counts as session expiry. |
| Proactive | Tokens are JWTs → `Jwt.tryDecode` reads `exp`. If less than 30s remain (`TokenManager.refreshLeeway`), refresh before sending. Non-JWT → skipped, rely on 401 only. |
| How the UI knows about logout | `TokenManager.events` (stream) → `AuthCubit` → `GoRouter.refreshListenable` re-evaluates `redirect`. The interceptor never touches the UI. |
| App startup | `AuthCubit` starts at `AuthUnknown`; the router stays on `/splash` until storage has been read. |

### Mock (current)

`AuthMockDataSource` makes no network calls and generates fake JWTs (`alg: none`):

- Login: any non-empty email/password → success.
- Access token TTL **1 minute**, refresh TTL 7 days, refresh token rotation enabled.
- To test the refresh flow: log in, wait > 1 minute, open the *Example* screen → the interceptor refreshes automatically (see logs at `/logs`).

Switching to a real backend: change 1 line in `injection.dart`

```dart
..registerLazySingleton<AuthRemoteDataSource>(
  () => AuthRemoteDataSourceImpl(getIt(instanceName: plainDio)),
)
```

and adjust `_parse()` in `AuthRemoteDataSourceImpl` to match your server's response shape.

### Adding a screen that requires login

By default **every route requires login**, except those in `Routes.public`. To make a route public, add it to that set.

## Logging

- `getIt<AppLogger>()` or inject `AppLogger` via constructor. Methods: `d / i / w / e`.
- `Bloc.observer = TalkerBlocObserver` → every event/transition is logged.
- `TalkerRouteObserver` logs every navigation.
- Open the in-app log screen: route `/logs` (linked from Home). Disable entirely in prod with `ENABLE_LOG=false`.
- Crash reporter (Crashlytics/Sentry): hook into `talker.handle` in `bootstrap.dart`.

## Theme

- Material 3, `ColorScheme.fromSeed`. Change the seed in `AppTheme._seed`.
- Colors outside the ColorScheme (success, warning…) are declared in `AppColors` (ThemeExtension), read via `context.appColors.success`.
- Light / Dark / System persisted via `ThemeCubit` + `AppStorage`.

## Adding a new feature

**Simple feature** (following `home`):

```
features/<name>/presentation/
├── cubit/<name>_cubit.dart
└── screens/<name>_screen.dart
```

Add the route to `app_router.dart` + `routes.dart`. Done.

**Complex feature** (following `example`):

1. `domain/entities/` — plain entities (`Equatable`).
2. `domain/repositories/` — `abstract interface class XxxRepository`.
3. `domain/usecases/` — one class per usecase with `call()`.
4. `data/models/` — `@freezed` DTO + `fromJson` + `toEntity()`.
5. `data/datasources/` — Dio calls.
6. `data/repositories/` — repository implementation wrapped in `guard()`.
7. `presentation/bloc/` — `sealed class` event/state, Bloc `switch` on `Result`.
8. `presentation/screens/` — `BlocProvider` + `BlocBuilder` with `switch` on state.
9. Register DI in `core/di/injection.dart`, route in `app/router/`.
10. Test the bloc with `bloc_test` + `mocktail` (see `test/features/example/`).

## Flutter 3.47 notes

- **Impeller** is the default renderer on Android and iOS — no flag needed; test blur/shader effects early.
- **Swift Package Manager** for iOS is enabled by default; the Podfile is kept because flavorizr needs it and some plugins don't support SPM yet.
- `RadioListTile.groupValue` / `onChanged` are deprecated → use `RadioGroup` (see `settings_screen.dart`).
- Dart 3.13: use `sealed class` + `switch` expressions instead of freezed unions for state/event.
